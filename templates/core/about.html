What AegisNet is

AegisNet is one integrated platform, not seven experiments. A shared topology model (nodes, links, costs, status) and one event timeline connect every module:

  1. Monitoring measures interfaces, throughput, latency and loss (psutil, ip, ping).
  2. Communication runs real TCP/UDP socket programs inside lab nodes.
  3. Packet Analyzer captures that exact traffic with tcpdump and decodes it with Scapy (Wireshark/TShark for inspection).
  4. Routing computes paths (Distance Vector, Dijkstra) on the same graph the lab uses.
  5. Fault detector probes real links and flows, raises alerts from thresholds.
  6. Recovery engine asks routing for an alternative path, installs it in the lab routers, verifies with ping, records the result.
  7. NS2 is a separate simulator (clearly labelled simulated) to compare normal / congested / failed-link networks.

Final demonstration script
  1. Start Django, sign in, show the Dashboard (mode badge says LIVE).
  2. sudo scripts/setup_network.sh → Dashboard “Probe links”: six links up, with addresses on the Monitoring page (CO1).
  3. TCP / UDP page: start servers, send a message and the sample file from PC A to PC B; read the handshake/FIN steps (CO2).
  4. Packet Analyzer: capture on r1 / r1-a with HTTP, DNS, TLS, TCP, UDP and ICMP traffic; open the TLS handshake and the PCAP in Wireshark (CO4).
  5. Routing Visualizer: load the lab topology, run Dijkstra and Distance Vector for A→B, disable r1-r2, run again and watch the route change (CO3).
  6. Fault & Recovery: start the background detector with auto-recovery, tick confirm, inject a failure on r1-r2.
  7. The detector raises link/interface alerts, the A→B path breaks, recovery installs A-R1-R3-R2-B and verifies with ping.
  8. Show the recovery history and the real routes (ip route on R1/R2). Click “Rollback” to restore.
  9. NS2 page: run scenarios A and C and compare throughput, delay, PDR and loss (CO3) — clearly simulated.
Safety rules built in
  • All privileged work goes through one allow-listed helper (scripts/ns_exec.py): lab namespaces and 10.10.0.0/16 / 127.0.0.0/8 only, no shell, read-only ip except lab route changes.
  • The host default route, DNS and internet connection are never modified; external addresses are refused by the clients, the helper and the views.
  • Disruptive actions need an explicit confirmation, have a dry-run, and a one-click rollback (restore_network.sh).
  • Packet capture is limited to lab interfaces (or loopback) and stores metadata only.
  • If namespaces or root are unavailable the system says so and runs a clearly labelled simulation instead.
